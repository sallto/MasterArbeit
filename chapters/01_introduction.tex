\chapter{Introduction}\label{chapter:introduction}

Just-in-time (JIT) compilation is a widely used technique for improving performance for applications, where the combined compilation and execution speed is critical. Such applications include dynamic runtimes, such as the Java virtual machine~\cite{jvm}, as well as database query acceleration~\cite{sql-jit}.
Since compile time directly contributes to end-to-end latency, fast machine code generation is especially important for JIT compilation. Recently, TPDE~\cite{tpde} has shown that the compilation speed of the LLVM~\cite{LLVM} unoptimized back-end can be improved substantially, while keeping a similar runtime performance. 

Since compile-time and runtime are fundamentally a trade off in JIT systems, many systems use multi-tiered approaches, trading off compilation time and code quality~\cite{tpde}. However, the gap in compile time between TPDE and optimized back-end of LLVM (\texttt{-O1}) is \todo{two orders of magnitude}, which leaves a large gap for programs that might benefit from a better code generation, but cannot justify the large compile time increase.

To address this gap, we present a novel register allocation approach built on top of TPDE, allowing for better code generation while keeping a comparatively fast compile time. Our work consists of two analysis passes, namely a lifetime analysis, which also generates next-use information, and a spill pass that identifies, which values to spill, as well as optimizing the spill locations to minimize spills in loops. During code generation, we introduce a repairing mechanism to handle instruction constraints, which allows us to generate better code for constrained instructions, such as division on \texttt{x86-64}.

On SPECint 2017 we achieve a \todo{30\%} runtime improvement over the LLVM -O0 back-end, while keeping a \todo{3x} faster compile time on optimized LLVM IR. Although this also incurrs a \todo{6x} compile time increase compared to TPDE. Still our works ahcieve a new pareto-optimum for compiling optimized IR, as it is significantly faster at compile tiime than LLVM-O1 while still providing a runtime improvement compared to both TPDE and LLVM-O0. 

The key contribution of our work include:

\begin{itemize}
    \item A lifetime analysis that generates next-use information in the same pass
    \item A spill analysis that identifies values to spill without relying on knowledge of the instruction semantics, or requiring modification to the IR.
    \item A simplified repairing mechanism to handle instruction constraints during code generation, without rolling back code generation.
\end{itemize}

In \autoref{chapter:approach} we present our approach. In \autoref{chapter:related_work} we discuss related work in register allocation, and how it relates to our approach. Next we evaluate our approach compared to TPDE, LLVM-O0 and LLVM-O1 in \autoref{chapter:evaluation}. Finally, we summarize our findings and discuss future work in \autoref{chapter:conclusion}.
